# Linux 服务器部署

系统由 Nginx Web、Node.js API 和 MySQL 8.4 三个容器组成。浏览器与 Android 使用同一套 API 和数据。

## 首次部署

服务器需安装 Docker Engine 24+ 与 Docker Compose v2，并开放 `WEB_PORT`（默认 8080）。

```bash
git clone <项目地址> personal-workbench
cd personal-workbench
cp .env.example .env
nano .env
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8080/api/health
```

必须把 `.env` 中的 `MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`ADMIN_PASSWORD`、`TOKEN_SECRET` 改成随机强密码。生产模式遇到示例默认值时 API 会拒绝启动。访问 `http://服务器IP:8080`，用 `ADMIN_USERNAME` 与 `ADMIN_PASSWORD` 登录。

## HTTPS 与域名

正式使用 Android App 时必须配置 HTTPS。可在本项目 Nginx 前放置 Caddy、Traefik 或宿主机 Nginx，并把域名反向代理到 `127.0.0.1:8080`。若 Web 与 API 不同源，把 Web 来源写入 `CORS_ORIGINS`，多个来源用逗号分隔。

## 运维

```bash
docker compose logs -f api
docker compose pull
docker compose up -d --build
docker compose exec mysql mysqldump -uroot -p personal_workbench > personal_workbench.sql
```

默认连接 Linux 服务器已经安装的 MySQL（`MYSQL_HOST=host.docker.internal`），不会启动第二个 MySQL 容器。若需要由 Compose 管理数据库，使用 `docker compose --profile bundled-db up -d --build`。容器 MySQL 数据保存在 `mysql_data` 命名卷；不要用 `docker compose down -v`，该命令会删除数据库卷。应用内“设置 → 数据管理”仍可导入/导出 JSON。

### 后续一键升级

上传新版本并保留服务器原有 `.env` 后执行：

```bash
chmod 700 deploy/update.sh deploy/rollback.sh
./deploy/update.sh
```

脚本会依次检查配置、在线备份 MySQL、保存当前镜像、构建并替换 API/Web、执行健康检查。新版本失败时会自动恢复旧镜像。需要手动回滚时执行：

```bash
./deploy/rollback.sh
```

数据库不会自动回滚，避免覆盖升级后产生的新业务数据；如升级包含破坏性数据库迁移，应先停机并单独制定恢复方案。

## 从旧版升级到多用户版

更新代码后直接重新构建即可，API 启动时会自动创建 `pwb_users` 与 `pwb_sessions`，无需手工执行 SQL。原来管理员名下的数据仍归 `ADMIN_USERNAME` 所有。

```bash
cd /opt/personal-workbench
docker compose up -d --build
docker compose logs --tail=100 api
```

首次升级会把 `.env` 中的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 写入用户表作为系统管理员。之后可在“更多 → 用户管理”添加普通用户或管理员、停用账号、重置密码、查询在线设备和强制下线。每个用户的数据均按 MySQL `owner` 字段隔离。

## 本地开发

先准备可访问的 MySQL，设置 `MYSQL_HOST` 等环境变量，再分别运行：

```bash
npm install
npm run dev:server
npm run dev
```

Vite 会把 `/api` 代理到 `http://127.0.0.1:3000`。可用 `VITE_DEV_API_TARGET` 覆盖目标。

## 数据模型

业务记录存入 MySQL 表 `pwb_records`。它使用 `(owner, table_name, record_key)` 复合主键，所有读写都附加当前登录用户条件。`pwb_users` 保存密码哈希与角色，`pwb_sessions` 保存在线设备、最后活动时间和强制下线状态。
